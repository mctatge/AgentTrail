# Validation

## Automated

`swift test` exercises drag boundaries and retained coordinates, shortcut inference, typing/pause/app boundaries, context separation, pagination, transaction rollback, literal search, read-only access, recovery, exports, path rejection, asynchronous evidence links, MCP requests, capture filters, writer exclusion, and raw Unicode/timestamp round trips.

`bash scripts/build-app.sh` builds a release executable, packages `dist/AgentTrail.app`, signs it locally, and verifies the signature.

`python3 scripts/smoke-test.py` uses the packaged binary in a disposable library to validate demo creation, CLI search, complete exports, synthetic training labels, MCP stdio requests/batches, read-only access, and database permissions.

`python3 -m unittest discover -s scripts -p 'test_*.py'` tests the publication gate, including index-versus-working-copy content, credentials, private paths, forbidden artifacts, symlinks/submodules, and binary/large files. After staging, `python3 scripts/check-publication.py` inspects the exact source being published. CI repeats that check, uses a pinned checkout action without persisted credentials, and never uploads generated recordings or app bundles. The packaging smoke test verifies bundled license/privacy notices.

These tests do not grant macOS privacy permissions or prove delivery of every physical device report. Live capture must be tested on the target macOS/app versions after granting permissions.

Capture regression tests run a real background CFRunLoop with a synthetic in-process source while the test's main thread is blocked for over half a second. They verify ordered key/pointer buffering, immediate pause suppression before UI delivery, counted overflow, capture-time foreground snapshots, shutdown/restart/installation failure, and intentional-versus-failure gap labels without rewriting old raw evidence. They do not inject OS events or require Input Monitoring.

### 0.2.1 capture-stall fix — 2026-09-08

A reported 0.2.0 session contained context/focus/gap records but no raw keyboard or pointer inputs. Its tap ran on the main thread and synchronously called application lookup and recorder callbacks, including clipboard access. The 0.2.1 fix isolates the tap from that work and distinguishes intentional exclusions from failures. All 33 tests and the packaged CLI/export/MCP smoke test passed. The installed app correctly displays legacy exclusion labels without rewriting raw records. The existing paused session was finished and preserved before the update. The updated ad-hoc build did not retain recognized Input Monitoring/Accessibility grants, so physical-input/live-resize verification is still pending user reauthorization; synthetic tests are not a substitute for that check.

### 0.2.2 permissions and Quit regression — 2026-09-08

A full quit/reopen of the unchanged 0.2.1 build made Screen Recording appear granted, while Accessibility remained unrecognized despite an enabled System Settings entry. The restart also reset capture choices made since the last Start. A regression test reproduced the default-mode timer failing to fire in AppKit's termination modal mode. The fixes register UI/termination timers in modal mode, refresh permission checks on activation and settings entry, and persist choices immediately. Tests use isolated preferences and temporary empty libraries, never real input capture. Live acceptance should verify Quit both while recording and from the settings sheet, saved choices after reopening, and permission recognition after manually authorizing the exact new build. An enabled System Settings row alone is not proof of effective access.

Live UI verification also reproduced Quit being ignored while Capture settings was open, even with no active session. The sheet's default termination veto bypassed the application delegate. The nonblocking-sheet bridge removes that veto for the three read/review/settings sheets, with an AppKit window attachment regression test. System authorization dialogs are not modified.

The final local 0.2.2 build passed all 37 Swift tests, the 10 publication tests, signature verification, and packaged CLI/export/MCP smoke checks. Live verification confirmed that Quit from the open Capture settings sheet exits the process and that all four selected capture options survive reopening without starting a recording. Existing sessions remained available. Reauthorization of the final ad-hoc build and live capture-to-Quit acceptance remain pending; no new physical-input recording was made during this verification.

Cursor-specific tests cover negative coordinates and aspect ratio, gaps/pauses/app switches, invalid points, stationary/vertical paths, event-range paging and session isolation, clock changes/equal-time samples, click/drag classification, and complete/resumable raw JSONL output. The synthetic example includes a straight drag, a curved move, and a right-button press for visual review. Check session-wide and action-scoped trails, playback, the time slider, per-sample stepping, speed selection, empty ranges, and page navigation. Verify that viewing a trail does not generate OS input or mutate recorded events.

## Explicit Save — further checks

The following checklist records broader acceptance coverage; only the checks explicitly reported above have been completed. Use isolated libraries and synthetic data wherever possible.

- Start, pause, resume, and stop a draft; verify that the durable library has no new session, events, actions, or screenshot files before Save. Existing saved data must remain unchanged.
- Review draft actions, linked evidence, search results, and cursor trails before saving. Confirm CLI and MCP cannot list or query the draft and that Export is unavailable.
- Save a draft into a library with existing rows. Verify session counts, screenshot bytes, action event ranges, and asynchronous evidence links after event IDs are remapped. Confirm CLI/MCP/export can now see the saved recording.
- Discard a draft, including one with screenshots; verify no new library entry or capture files exist and a new recording can start. Confirm Save/Discard must resolve a draft before another recording or GUI example starts.
- Inject a Save failure and verify that no incomplete session is exposed, the draft remains reviewable, and retry or Discard works. Check callbacks and refreshed views cannot restore a discarded draft or attach prior evidence to a later draft.
- Exercise Quit with an active recording, paused recording, stopped draft, and open settings/review sheet. Verify **Save and Quit**, **Discard and Quit**, and **Cancel** each honor the chosen behavior; a Save failure must keep the app open.
- Force-quit with an unsaved synthetic draft and reopen; verify that draft is absent and previously saved recordings remain. Separately verify recovery of a legacy on-disk recording/paused session.
- Verify capture preferences survive a quit without saving a recording, and that merely opening settings or the app does not start capture.
- Measure memory growth in a long disposable recording with screenshots enabled; validate input-gap reporting under load. In-memory storage does not establish protection against OS swap or crash dumps.

## First live session

Use a disposable document and restrict the app allowlist if helpful. Record the following sequence, inspect the unsaved timeline and raw events, and save only the test recordings you intend to keep:

1. Enter several values, including a shifted character and a non-ASCII character with text enabled. Inspect physical key codes, modifiers, and optional Unicode separately.
2. Select `B2:B10`, press Command-D, then undo. Confirm the shortcut appears and any fill-down label remains an inference. With Excel context enabled, check the range's separate observation timestamp.
3. Drag across cells, scroll horizontally and vertically, right-click, and double-click. Check button IDs, click counts, coordinates, and grouped drag boundaries.
4. Switch to a browser, click a labeled button, then return. Check app-focus records and available accessibility labels. A canvas with no element labels is an expected limitation.
5. Add a bookmark, pause, type a disposable distinctive phrase, resume, and stop. Confirm there are no ordinary key/pointer inputs within the pause interval. Later context or screenshots can show text entered while paused if it remains visible; clear that phrase before resuming if testing its absence from all subsequent observations. The stopped recording should remain an **Unsaved** draft.
6. Choose **Save recording**, fully quit, and reopen the same app with the same library. Export the reopened recording and verify its session UUID, complete raw evidence, action ranges, and asynchronous links. If screenshots are enabled, check the captured window, timing fields, attachment paths, and image bytes.
7. Start another disposable session and force-quit without saving. On relaunch, verify that this unsaved draft is absent and the previously saved recording is intact. New in-memory drafts cannot be recovered.
8. Export and query through a read-only MCP client. Check pagination, raw event links, and separation of observed facts from inferences.
9. Resize AgentTrail and another application's window, open/close a menu, then type a disposable phrase and drag in the other app. Confirm raw key/pointer inputs continue after switching apps and during ordinary resizing. For the other app, inspect for a `window_resize` event with `previousWindowFrame` and `windowFrame`; compare it with the raw drag without treating either record as proof of causation. AgentTrail's own controls are intentionally excluded, but there should be no listener timeout. Apps that do not expose focused-window geometry may produce only the raw pointer evidence.

Record results with macOS version, app version, input device/layout, capture options, and any gaps. Do not publish real recordings containing personal information as test fixtures.

### Disposable acceptance protocol

Use the exact final app build throughout a run. Keep the library, document, exports, and any independent witness material in a local disposable directory outside the repository. Do not fault, clear, or migrate the normal library. A human must perform the physical inputs; generated OS events and synthetic examples test different boundaries.

Record a receipt with the executable path and SHA-256, version/build and signing identity, macOS and target-app versions, device and keyboard layout, options/allowlist, session UUID, and expected-versus-observed action ledger. Record deviations and gaps without silently replacing the run. For a short test, a human checklist or consent-safe external video can provide independent action evidence. Recorder context is not an independent witness.

| Check | Disposable procedure | Required evidence |
| --- | --- | --- |
| Effective permissions | Relaunch the exact app and inspect its own access checks. Test physical keys/pointer, AX context/geometry, and screenshots separately | Input Monitoring delivers raw inputs; Accessibility supplies supported AX observations; optional Screen Recording produces a real image. Enabled System Settings rows alone are insufficient |
| Keyboard | Type a short prewritten ASCII token with known press/release counts, shifted characters, a shortcut, held-key repeat, and a layout-appropriate non-ASCII sequence | Raw `key_down`, `key_up`, modifiers, repeat fields, timestamps, and optional Unicode agree with the ledger. ANSI key labels, per-event Unicode, and final composed application text are distinct evidence |
| Pointer and app attribution | Move, single/double/right-click, drag, scroll on both axes, switch between allowed disposable apps, and click an inactive window | Raw button IDs/click counts, coordinates, drag boundaries, deltas, app/bundle, target PID or labeled foreground fallback; input continues after switching apps, menus, and ordinary resizing |
| Pause/resume | Exercise the UI and global shortcut separately. Type/move/resize while paused, then resume and enter a new token | Ordered pause/resume markers; no ordinary key/pointer inputs during pause; resumed inputs present. Inspect timestamps at the shortcut boundary to test whether asynchronous geometry/context/screenshots also stop there; the main-thread gate can lag the input-buffer gate. Clear paused text before resume if testing global absence from later observations. Geometry restarts with a fresh baseline |
| Geometry | In an AX-supported app, hold the initial size, resize, then hold the final size for at least one second. Also move without resizing, switch focused windows, and resize while paused/excluded | `window_resize` has correct previous/current dimensions, app/PID and notification/poll source; pure moves/new-window baselines do not produce resize records. Unsupported AX geometry is reported as unverified coverage, not a successful negative check. Drag and geometry do not prove causation |
| Draft isolation | Seed a saved synthetic sentinel in the disposable library, then Start/Stop a physical recording without Save | Unsaved review works; durable session/event/action rows and attachment files remain at baseline; CLI/MCP cannot see the draft; GUI Export is unavailable |
| Quit Cancel | While recording, request Quit and choose Cancel; return to the target app and physically enter a distinct token. Repeat while paused/stopped and with settings/cursor-review sheets open | Same draft UUID and state remain; no premature `session_end` for active/paused capture or new end marker for a stopped draft; post-Cancel physical input arrives when active; paused capture stays paused; saved library remains unchanged |
| Other cancellation | Cancel Discard confirmation; after saving, open Export and cancel its folder panel | Draft remains after canceled Discard; canceled Export creates no dataset and leaves saved evidence unchanged |
| Save, full Quit/reopen | Stop immediately after a distinctive final key/click; inspect its raw evidence, Save once, export a baseline, fully quit, verify process exit, reopen the same app/root, and export to another new folder | One saved session with the same UUID/options; the final inputs precede `session_end`; draft-to-saved payloads agree after ID/link remapping; reopened saved JSONL and attachment bytes equal the baseline; the sentinel remains unchanged |
| Complete export | Parse all pages/lines from the reopened session, beyond the GUI inspector's first 200 raw records | Counts match saved rows; every `relatedEventID`, action endpoint, and attachment resolves within the session; images decode and show the intended disposable window; raw/derived evidence stays distinct; both training verification flags remain false |
| Save and Quit / Discard and Quit | Use separate active, paused, and stopped disposable drafts for each choice | Save and Quit persists exactly once after finalization; Discard and Quit adds no session/frames; both exit, preserve the sentinel, and reopen idle |
| Caught Save failure and retry | Use a draft containing an attachment and a controlled attachment-path conflict in a separate disposable library, following the synthetic failure fixture pattern | No partial session/rows/new files, draft review survives, Quit is canceled on failure, explicit retry succeeds once; Quit during a pending Save does not start an automatic retry |
| Unsaved unexpected exit | Force-quit only the separate disposable instance with a new unsaved draft, then reopen | Unsaved draft is absent; sentinel and earlier saved physical session remain intact. Legacy on-disk recovery is a separate compatibility test |
| Permission denial/loss | As separate human-controlled negative cases, deny or revoke only the tested app's relevant grant; preserve and restore the chosen setting | Actual delivery/AX/image behavior is documented, denied tap startup does not leave a saved session, and recovery requires a successful new test after relaunch. Mid-session revocation is not proven safe by the periodic permission badge alone |
| Sustained capture | Repeat the short run after reopening and run a predeclared longer disposable session on the target hardware | Duration, process memory, counts and all gaps retained; overflow/timeout/failure labels inspected; limits qualified by device, layout, apps and options |

Successful acceptance establishes capture of the tested sequence and preservation through explicit Save/reopen/export. It does not establish capture of every hardware report: macOS can coalesce events before the recorder, buffers are bounded, and geometry/screenshots are sampled. Missing geometry can reflect silent AX unavailability; permission refresh has no explicit model-level stop transition for mid-session revocation. The global pause shortcut closes the input-buffer gate before the main thread applies pause and invalidates asynchronous observations; inspect that interval instead of assuming an exact shared cutoff. Caught-save rollback also does not prove crash atomicity across SQLite rows and screenshot files. Keep these limits separate from the tested results.
